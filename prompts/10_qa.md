# QA Design Prompt

You are an AI tutor designing a self-check Q&A section.

> ⏸ **On-demand only.** 신규 논문 기본 빌드 범위에서 제외됨. 사용자가 ⑥ 콘텐츠 작성을 명시 요청한 경우에만 실행한다 (CLAUDE.md "기본 빌드 범위" 정책).

## Pipeline Position

- **Stage:** 9 (QA Content Design — ⑥ `tab-qa`)
- **Input:** `structured.json`, Stage 4 산출물 (dissection), Stage 7 산출물 (knowledge),
  **+ 사용자 학습 메모 (`papers/[name]/study/{Short}_study_notes_*.json` — 있으면 의무 입력)**
- **Output:** `papers/[name]/tabs_data/qa.json` — Stage 10에서 Claude가 그대로 HTML 마크업으로 변환
- **렌더링 위치:** ⑥ `tab-qa` (학습 기초 Q & A)

## 🔴 사용자 학습 메모 반영 (의무, 2026-07-08)

Paper Study 탭의 메모 드로어에 사용자가 남긴 질문들은 Q&A 탭의 **1순위 재료**다.
이 파이프라인을 실행하기 전에 반드시:

1. `papers/[name]/study/`에서 `{Short}_study_notes_*.json` 중 **가장 최신 파일**을 읽는다.
   `notes.memo`는 **자유 서식 텍스트 메모장**이다 — 질문·의문·확인할 것이 줄바꿈으로 섞여 있으므로,
   Claude가 텍스트에서 개별 질문/의문점을 직접 추출한다 (질문이 아닌 단순 메모는 맥락 참고용).
   구버전 파일은 JSON 배열 `[{t, q}]`일 수 있다 — 둘 다 처리.
2. 파일이 없으면 사용자에게 "Paper Study 탭에서 내 노트 내보내기를 먼저 해달라"고 요청한다
   (메모를 안 쓴 논문이면 그냥 표준 3-카테고리로 진행).
3. **메모의 모든 질문을 하나도 빠뜨리지 않고 답한다.** 배치 규칙:
   - 전용 카테고리 **`M` — "내가 남긴 질문"**을 만들어 **카테고리 목록 맨 앞**에 둔다
     (자기 질문의 답부터 확인하는 것이 학습 동기상 가장 강력하므로).
   - 각 항목의 `q`는 사용자 원문을 존중하되 문장만 다듬고, `a`는 본문 근거(§·Table·Fig 번호)를
     짚으며 답한다. 논문이 답하지 않는 질문이면 그 사실 자체를 명시하고 합리적 추정을 구분해 적는다.
   - 사용자 질문이 표준 카테고리(A/B/C)의 예정 질문과 겹치면 M쪽에 배치하고 표준 쪽에서는 뺀다 (중복 금지).
4. qa.json의 M 카테고리 항목에는 `"from_memo": true`를 달아 출처를 남긴다.

### 🔴 군집화 — 카드 수 상한 없음, 관련 질문은 한 카드로 (정본, 2026-09-10)

메모 항목 하나 = 카드 하나가 아니다. **추출 → 군집화 → 작성** 3단계로 처리한다.

1. **추출** — 메모 텍스트에서 개별 질문/의문점을 빠짐없이 뽑는다. 이미 생성한 질문과 의미가 겹치는 것만 제외.
2. **군집화** — 남은 질문을 **주제·논리적 연결 기준으로 묶는다.** 한 묶음 = 같은 메커니즘·같은 섹션·같은 주장을
   서로 다른 각도에서 묻고 있는 항목들. **묶음 하나가 카드 하나**다. 연결되는 항목이 없으면 단독 묶음(카드 1장).
   - 억지 병합 금지 — 근거가 다르고 답의 전제가 공유되지 않으면 별개 묶음이다.
   - 한 묶음의 하위 질문이 5개를 넘으면 논리적 경계(메커니즘 단계·주장 단위)로 쪼갠다.
3. **작성** — **개수 상한은 없다.** 이번 실행에서 나온 새 질문은 전부 다루고 다음 실행으로 미루지 않는다.
   카드 수는 상한이 아니라 묶음 수, 즉 메모의 실제 주제 수가 결정한다.
   - 카드 제목(`title`)은 묶음 전체를 포괄하는 **하나의 질문**으로 쓴다.
   - 본문은 하위 질문을 따로따로 나열해 각각 답하는 형태가 **아니라 하나의 연결된 설명**이다.
     한 질문의 답이 다음 질문의 전제가 되도록 논리 사슬로 잇고, 각 하위 질문이 본문 어디에서 답해지는지 드러나게 쓴다.
   - 각 항목에 `"covers": ["메모 원문 질문", ...]`(그 카드가 답하는 메모 항목 원문 목록)을 남긴다.

**마크업** — 묶음 카드는 헤더(`.qa-mem-q`) 바로 아래, 요약(`.qa-mem-tldr`) 위에
`<ul class="qa-mem-covers"><li>메모 원문 질문</li>…</ul>` 를 둔다. 학습자가 자기 메모의 어느 항목이
다뤄졌는지 보기 위한 것이므로 **하위 질문이 1개뿐이면 이 블록은 생략**한다. CSS는
`tools/qa_button_inject.py` 가 주입한다(v4 토큰 `--muted`/`--line`/`--accent-mid` 사용).

**동기 (상한이 만든 영구 차단)** — 이전 정책은 "한 번에 최대 6개"였다. 그런데 로컬 브릿지는 성공 시
메모 **전체** 해시를 `study/.qa_state.json#processed_hash` 에 봉인하고, 클라이언트·서버 게이트가
같은 해시를 `nochange` 로 차단한다. 따라서 상한에 걸려 미뤄진 질문은 사용자가 메모를 고치지 않는 한
영구히 생성되지 않았다(papers 26·30 이 정확히 6개에서 멈춰 있었다). 상한 제거가 그 직접 결과다.
브릿지 쪽 안전장치: `deferred > 0`(남긴 질문 있음) 이면 `processed_hash` 를 갱신하지 않고,
`noop`(새 질문 없음 판정) 은 `processed_hash` 대신 `noop_hash` 에만 기록해 우회를 남긴다
(`tools/qa_bridge.py` v1.2).

### 🔴 `.qa-mem-*` 클래스 화이트리스트 — 목록 밖 클래스 금지 (정본, 2026-09-10)

메모 Q&A 카드·보완 학습 카드의 CSS는 `tools/qa_button_inject.py` 가 HTML에 주입한다.
정의된 클래스는 아래가 전부이며, **여기 없는 클래스를 새로 지어내면 스타일이 없어 맨 문단으로 떨어진다.**
필요한 표현이 목록에 없으면 가장 가까운 것을 쓰거나 클래스 없는 표준 HTML 태그(`<p>` `<ul>` `<ol>`
`<table>` `<strong>` `<em>` `<code>` `<figure>`)를 쓴다. **새 `<style>` 블록을 파일에 추가하지 않는다.**

| 클래스 | 태그 | 역할 |
|---|---|---|
| `qa-mem-root` | div | 카드 묶음 컨테이너. 메모 쪽 `data-qa-mem-root`, 검토 쪽 `data-review-supp` |
| `qa-mem-cat` | p 또는 h3 | 카테고리 라벨. root 바로 아래면 그룹 라벨, 카드 안이면 소제목. 두 태그 렌더 동일 |
| `qa-mem-card` | article | 카드 (`data-qid` 필수) |
| `qa-mem-q` | h3 | 카드 제목 |
| `qa-mem-covers` | ul > li | 이 카드가 답하는 메모 원문 질문 목록 (하위 질문 2개 이상일 때만) |
| `qa-mem-tldr` | p | 요약 한 문단 ("TL;DR" 라벨 텍스트 금지) |
| `qa-mem-callout` + `key`/`warn`/`safe` | div | 강조 박스 |
| `qa-mem-table-wrap` > `qa-mem-table` | div > table | 넓은 표. wrap 이 가로 스크롤을 맡는다 |
| `qa-mem-math` | div | display 수식 블록 (안에 `$$...$$`) |
| `qa-mem-math-note` | p | 수식 바로 아래 각주 한 문단 |
| `qa-mem-figcap` | figcaption | 카드 안 이미지 캡션 |

같은 목록이 `tools/qa_bridge.py` 의 `PROMPT_TEMPLATE`·`REVIEW_PROMPT_TEMPLATE` 안에도 들어 있다.
목록을 늘릴 때는 **주입기 CSS·두 프롬프트·이 표 셋을 함께** 고친다.

> 정본 학습 사례: papers 30 의 헤드리스 run 이 `qa-mem-cat`·`qa-mem-figcap`·`qa-mem-math`·
> `qa-mem-math-note` 를 지어냈고 CSS가 없어 `<p class="qa-mem-cat">내가 남긴 질문</p>` 이 스타일
> 없는 맨 문단으로 렌더됐다. 프롬프트가 허용 클래스를 주지 않은 것이 원인이다 (2026-09-10 수정).

## 역할

학습자가 **논문을 다 읽은 뒤** 자가 점검할 수 있는 Q&A 세트를 설계한다.

이건 평가 시험지가 아니다. **학습자가 혼자 읽었을 때 모호하게 남았을 만한 부분을 미리 짚어주는** 학습 보조 도구다.

## 표준 카테고리 구조 (정본)

3개 카테고리, 각각 2~3개 질문. 총 6~10 질문 권장.

| ID | 제목 (예시) | 다루는 것 |
|---|---|---|
| **A** | 기초 지식 / 지형도 | 논문 도메인의 큰 그림. 이 분야를 처음 보는 학습자가 길을 잃지 않게 하는 입문 |
| **B** | 메커니즘 | 논문 메서드의 작동 원리. "왜 이 단계가 필요한가" "왜 이 순서인가" 같은 인과 |
| **C** | 실험 해석 | 결과 표/그림을 어떻게 읽을 것인가. 수치의 함의, 함정, 비교의 정당성 |

이 3-카테고리는 모든 논문에 통용된다. 카테고리 ID는 `A`, `B`, `C` 고정이지만 제목은 논문에 맞게 조정 가능.

## JSON 스키마 (정본)

```json
{
  "categories": [
    {
      "id": "A",
      "title": "LVLM 추론의 지형도",
      "questions": [
        {
          "qid": "q1",
          "title": "한 프레임이 토큰이 되는 길",
          "user_question": "(선택) 학습자가 던질 법한 원래 질문 형태",
          "tldr": "1~2문장 한줄 요약 답변",
          "blocks": [
            { "type": "html",    "content": "..." },
            { "type": "table",   "headers": ["...", "..."], "rows": [["...", "..."]] },
            { "type": "math",    "tex": "...", "explanation": "..." },
            { "type": "callout", "variant": "key", "content": "..." }
          ]
        }
      ]
    },
    { "id": "B", "title": "...", "questions": [...] },
    { "id": "C", "title": "...", "questions": [...] }
  ]
}
```

### 필드 규약

- `qid`: `q1`, `q2`, ... 논문 전체 유일
- `title`: 한 줄 짧은 질문 (15자 이내 권장)
- `user_question` (선택): 학습자가 자연어로 던질 법한 형태 ("이건 왜 이렇게 되는 거예요?" 식). title보다 길어도 됨.
- `tldr`: 한 줄 요약 — 1~2문장으로 답을 압축. 본문을 다 읽지 않아도 이것만으로 핵심을 가져갈 수 있어야 함. (스키마 필드명은 `tldr`로 유지하되, **HTML 렌더 시 "TL;DR" 같은 라벨 텍스트를 붙이지 않는다** — `.qa-mem-tldr` 박스에 요약 문장만 넣는다.)
- `blocks`: 본문 블록 배열. 4가지 type만 허용 (`html`, `table`, `math`, `callout`).

### 블록 타입별 형식

#### `html`
```json
{ "type": "html", "content": "<p>...</p>" }
```
자유 마크업. 위젯 SVG도 여기 포함. 인라인 수식은 `$...$`.

#### `table`
```json
{
  "type": "table",
  "headers": ["조건", "FastV", "Ours"],
  "rows": [
    ["VideoMME", "63.4", "65.4"],
    ["...", "...", "..."]
  ]
}
```
간단한 비교 테이블. 5×5 이하 권장.

#### `math`
```json
{ "type": "math", "tex": "S_t = \\frac{X_{t-P}^\\top X_t}{\\|X_{t-P}\\|\\,\\|X_t\\|}", "explanation": "이 식은 ..." }
```
display 수식 + 한 줄 설명. JSON에서 `\\` 두 번 (`rules/math_rules.md` 참조).

#### `callout`
```json
{ "type": "callout", "variant": "key|warn|safe", "content": "..." }
```
강조 박스. `variant` 3종:
- `key`: 핵심 인사이트 (초록 계열)
- `warn`: 주의/함정 (빨강 계열)
- `safe`: 부드러운 부연 (회색/베이지 계열)

## 작성 원칙

### 1. 한 줄 요약이 본문보다 먼저 결정되어야 한다
질문을 만들 때 **요약(`tldr`)을 한 문장으로 먼저 쓰고**, 그 다음에 그 답이 왜 그러한지를 풀어쓰는 본문 블록을 만든다. 요약이 흐릿하면 그 질문은 폐기. (렌더 시 "TL;DR" 라벨은 붙이지 않는다.)

### 2. 한 질문은 한 가지만 답한다
"X의 의미와 Y의 차이점, 그리고 Z의 한계"를 하나의 질문에 묶지 말 것. 쪼개라.

### 3. 블록 수 제한
질문당 본문 블록 2~5개. 6개 이상이면 그 질문은 너무 큰 주제다 — 두 개로 쪼개거나 dissection 카드로 보낸다.

### 4. 카테고리 A는 도메인 진입점
독자가 이 분야를 처음 본다고 가정. ViT, Token, KV-Cache, LoRA 같은 기초 개념을 묻는 데 부담이 없어야 한다. **단, 논문에서 직접 사용하는 개념만**.

### 5. 카테고리 B는 인과 사슬
"왜 이 순서인가" / "왜 이 단계만 deep층에서 하는가" / "왜 이 트릭이 정합성을 보장하는가" — 모두 dissection의 Execution Logic / Hidden Assumptions과 연결되어야 한다.

### 6. 카테고리 C는 표/그림 읽기
"Table 1에서 X가 유독 떨어지는 이유" / "Figure 9의 speedup이 모델 크기에 따라 다른 이유" — 본문이 명시한 결과를 **다시 읽어주는** 게 아니라, **암시만 한 함의를 짚어주는** 질문이어야 한다.

### 7. 커스텀 위젯은 한두 개만
Q1에 패치 → 1D 시퀀스 변환 애니메이션 같은 인터랙티브 위젯은 카테고리 A의 첫 질문 정도에 한 번 정도 둔다. 모든 질문에 위젯을 달면 본질이 흐려진다.

**위젯 클래스 규약 (`rules/component_rules.md` 참조):**
- 논문 prefix를 붙임 (예: `q1-patch`, `q1-token`, `q3-bar`)
- vanilla JS, 외부 라이브러리 의존 없음
- 위젯 마크업은 `html` 블록의 `content` 안에 인라인

- 카테고리 3개 (A/B/C 고정)

## 이미지 생성

> Claude Code의 Bash tool로 `codex ...` 명령을 직접 실행해 ImageGen으로 PNG를 만든다. 별도 플러그인·MCP 자동화 없이 Bash 한 줄. 결과는 곧장 base64로 박아 `<figure class="concept-figure">` 정본 컴포넌트로 인라인. **생성 직후 Claude가 PNG를 Read로 열어 §11.8.6 체크리스트를 확인**하고, 미달이면 프롬프트를 고쳐 재생성한다. 그 뒤 사용자 검수는 사후.
>
> **호출 형식 (6계명 — Bash·UTF-8 prompt.txt·ASCII 인자·stdin null·스타일/출력 명시·이미지 내 논문 제목 금지)
> + 검증된 명령 템플릿: `rules/component_rules.md` §11.2~11.3.**
> **🔴 prompt.txt 본문을 어떻게 채우는지는 `rules/component_rules.md` §11.8이 정본** — 5블록 구조 · 패널마다
> (시각 형태 + 실제 수치 + 영어 캡션) 3요소 · 이미지 종류별 밀도 등급 · 병렬 호출 격리 · 검수 체크리스트 ·
> 실패 모드별 처방. 이 절을 건너뛰면 여백만 크고 정보량이 적은 그림이 나온다 (반복 실패의 단일 원인).

이 단계에서 생성 가능한 이미지:
- 카테고리 A의 **도입 일러스트** (도메인 큰 그림 — 예: "비디오 → 토큰 변환의 길")
- 각 질문의 **요약 보조 이미지** (한 장으로 답을 시각화)
- 카테고리 C의 **표·그림 해석 보조** (예: "Figure 9가 무엇을 말하는가"를 단순화한 일러스트)

저장 / 임베드:
- 저장 경로: `papers/[name]/assets/generated/`
- 파일명 규약: `qa_<qid>_<purpose>.png` (예: `qa_q1_intro.png`, `qa_q7_table_reading.png`)
- HTML 임베드: `qa.json#blocks`의 `html` 블록 안에 `<img>` — **Stage 10에서 base64 인라인으로 변환** (CLAUDE.md 자산 임베딩 정책). `<img src="assets/generated/...">` 외부 참조는 개발 미리보기 한정.
- **인터랙티브 애니메이션 위젯은 JS로 구현** (예: `q1-patch`, `q1-token` stepper). ImageGen은 정적 보조 일러스트에만.

질문당 이미지 0~1개가 적정. 모든 질문에 이미지를 붙이면 학습 흐름이 끊긴다.
