# 논문 소개 영상 규칙 (Stage 13)

모든 논문은 8탭 학습 HTML과 함께 **소개 영상 한 편**을 만든다. 학습 HTML을 열기 전에 보는 10~15분 다큐멘터리형 영상이다.

- **시작 뼈대:** `templates/paper_base/video/` (`make_video.py <논문> new`가 논문 `video/`로 복사한다 — 원고 `기획안.md`, `spec.py`, `scenes.js`, `clipspec.py`, `CREDITS.md`, `assets/sources.json`). 배포본에는 완성된 영상 예제가 없다.
- **도구:** `tools/video/` (`make_video.py` 하나로 모든 단계를 실행한다). 클립 엔진은 motion-broll 스킬(배포본 `skills/motion-broll/`, 설치 위치 `.claude/skills/motion-broll/`, 아래 "스킬 설치").
- **형식이 굳어진 경위:** 모체 작업 폴더의 AI/CS 논문 영상 두 편(모체 사례 — 배포본 미포함)에서 사용자 승인으로 확정됐다. 이 문서에 남은 "모체 사례" 수치·장면 예(스티커 사진, 크롭 앤 줌 등)는 **예시일 뿐**이며, 다른 분야 논문은 같은 구조에 그 분야의 사례·증거를 넣는다(`config.json#domain`).

**스킬 설치 (Stage 13 전):** `.claude/skills/motion-broll/SKILL.md`가 없으면 `skills/motion-broll/`을 `.claude/skills/motion-broll/`로 복사해 설치한다(프로젝트 스킬 폴더). `python tools/video/make_video.py - doctor`(또는 `- setup`, 클립 단계 `clips-build`·`beats`·`clips-render`)가 없을 때 자동으로 복사하고, Windows에서는 `setup/8_install_video.bat`도 같은 일을 한다. `.claude/skills/`는 설치 대상이라 git에서 제외한다 — 고칠 때는 `skills/motion-broll/`을 고치고 `- setup`으로 다시 복사한다.

## 2. 형식: 연구 다큐멘터리

노벨상 연구 리뷰 영상처럼 **저자의 고민 → 관찰 → 실험 → 성과 → 남은 문제**가 이야기로 흐른다.

- **내레이터(N)** 한 명이 처음부터 끝까지 설명한다. 3인칭("이 논문은", "저자들은")으로 말한다.
- **저자 목소리(Q)** 는 논문 문장 인용으로만 나온다. 문장은 `translations/manual.json`의 번역본 그대로(필요하면 핵심 절만) 읽고, 화면에는 PDF 원문 지면에 형광펜이 지나간다. 인용 4~8개.
- **주인공 예시 하나.** 논문의 대표 정성 사례(입력 하나 + 질문 하나)를 프롤로그에서 실패로 보여 주고, 해법 장에서 방법을 통과시키고, 에필로그에서 다시 보여 준다(모체 사례: 냉장고 스티커 "Warning" 사진). 정성 사례 그림이 없는 분야·논문은 표의 대표 수치 쌍이나 실험 조건 하나를 주인공으로 잡는다.
- **예시 이미지 우선순위 (사용자 지시 2026-11-20).** 화면에 나오는 입력 이미지·사례는 ① 논문에 있는 자료(정성 사례 그림, 원문 크롭)를 먼저 쓴다. ② 논문에 없으면 codex ImageGen으로 예시 사진을 만들거나(`video/assets/`에 `prompt_*.txt`와 함께 저장) ③ 논문이 쓰는 벤치마크·샘플 데이터셋에서 고른다(출처 표기). ②·③은 화면에 "예시 사진"을 단다. 사진 자리를 회색 도형으로 그리지 않는다(모체 사례: 입력 이미지를 도형 선반으로 그려 지적받음).
  - **출처 목록 `video/assets/sources.json`.** `video/assets/`의 이미지마다 `{"파일명": {"kind": …}}`를 적는다. kind는 `paper`(+`ref`: fig_N·table_N·쪽), `codex`(+`prompt`: 같은 폴더의 프롬프트 파일), `dataset`(+`credit`: `CREDITS.md`에 있는 문자열), `derived`(+`from`: 목록 안의 원본, `how`: 자른 좌표·크기). 확대 대상이 있으면 원본 픽셀 좌표를 `target`에 적고, 화면의 상자·도구 호출 좌표를 그 값에 맞춘다(예: `"target": [1037, 644, 1210, 745]`). 형식: `{"crop_example.png": {"kind": "codex", "prompt": "prompt_crop_example.txt", "target": [x0, y0, x1, y1]}}`.
  - **사진 프롬프트 (`video/assets/prompt_<이름>.txt`, UTF-8).** codex 6계명(CLAUDE.md, 호출 형식 `rules/component_rules.md` §11.2~11.3)을 따른다. 인포그래픽용 §11.8(패널·수치·캡션)은 사진에 적용하지 않고, 대신 아래를 쓴다.
    1. 첫 줄에 용도("사실적인 사진 한 장 (영상 속 ~ 설명용 예시 입력 이미지)").
    2. 장면: 무엇이 어디에 있는지. 질문이 가리키는 대상은 **사진 대비 위치·크기를 %로** 적고, 원래 크기에서 얼마나 작고 확대하면 어떻게 보여야 하는지 쓴다(모체 사례: 폭의 약 8%, "원래 크기로는 겨우, 확대하면 선명하게").
    3. 글자 통제: 사진 속 글자는 필요한 것만 따옴표로 정확히 적고, "그 외에는 읽을 수 있는 글자·로고·브랜드명이 없다"고 쓴다.
    4. 스타일: 사실적인 사진, 자연광, 전체 초점, 과한 채도 없음, **사람 없음**(실존 인물·얼굴 금지).
    5. 풀 블리드 + `NOT a transparent cutout`, 해상도(기본 1536x1024), 저장 경로.
    6. 마지막 줄 `NO paper title at top, NO standalone header, NO author names.` (+ 캡션·테두리·덧씌운 글자 없음).
  - **순서:** 프롬프트 작성 → `make_video.py <논문> check-assets`(G11 FAIL 0) → codex 호출(`--cd`로 격리한 폴더, `< /dev/null`) → 결과를 직접 열어 대상이 원래 크기에서 작고 확대 크롭에서 읽히는지, 지시하지 않은 글자·로고·사람이 없는지 확인(미달이면 프롬프트를 고쳐 다시, 최선본 백업) → `sources.json` 기록 → 클립에 사용 → `check-assets` 다시.
- **실험 노트.** 어블레이션은 연구가 한 단씩 진행된 것처럼 같은 그래프가 이어 그려진다. 화면에 "논문 어블레이션 순서로 재구성"을 표기한다.
- 사람 얼굴·아바타·대담 장면은 없다. 하단 고정 문구 "본 영상은 논문을 바탕으로 재구성한 영상입니다."(자막 레이어, 말로 고지하지 않음).

**거부된 형식(다시 쓰지 않는다):** 논문 지도 위 종이 슬롯과 칩(v2, "피피티 같다"), 사진 한 장에 장면 12개(v3, "산만하다"), 만화책 칸(v4), 연구 노트 위 펜과 저자 특강(v5, "PPT 같다"). 제목 슬라이드 + 글머리표, 원문 그림에 상자만 치는 장면, 슬라이드로 그대로 쓸 수 있는 프레임은 실패다.

## 5. 원고 (`video/기획안.md`)

형식(파서가 읽는 규칙):

```
## 2. 원고
### 프롤로그 · 스티커
| 컷 | 화자 | 말 | 출처 |
|---|---|---|---|
| c01 | N | 냉장고 문에 노란 스티커가 붙어 있습니다. … | fig_5 |
### 1장 · 보이지 않는 글씨
| c10 | Q | 효과적이고 효율적인 RoI 식별 방법은 … | p_intro_3_s6 |
...
### 에필로그
...
## 3. 사실 검토가 필요한 항목
```

- `### 프롤로그 · 제목`, `### N장 · 제목`, `### 에필로그`가 장이다. `## `가 나오면 원고가 끝난다.
- 컷 id는 `cNN` 또는 `cNNa`. 화자 `N`(내레이터), `Q`(저자 인용), `—`(무음 4.5초 — 말 칸은 읽지 않으므로 `(무음)`처럼 적고 출처 칸은 비워도 된다). 목소리는 화자 칸이 정한다(N → 내레이터 음원, Q → 인용 음원, 6절). 컷마다 목소리를 따로 고르는 칸은 없다.
- **출처 칸 필수:** sentence_id, 자산 id(`fig_N`/`table_N`/`box_N`), `config.meta`. 논문 문장이 아닌 풀이 컷은 `설명`, 비유 컷은 `비유`를 함께 적고, 그 장면 화면에 "도식"/"비유"/"예시" 표기를 단다.
- 원고 앞에 `## 0.` 절로 이 판의 의도·바뀐 것을, 뒤에 `## 3. 사실 검토가 필요한 항목`(계산한 값·해석한 문장의 근거)을 둔다.

**학부생 눈높이 규칙** (모체 사례의 학부생 검토 개선안 7개에서 확정):

1. 방법 전체 그림(한 문장 요약 + 추론 흐름)을 실마리 장 끝에 먼저 보여 주고, 세부는 그 뒤에 푼다.
2. 학습할 때와 쓸 때가 다르면 그 연결을 한 컷으로 따로 말한다.
3. 식은 **1개만** 읽는다. 기호마다 말로 읽고 "이 식은 ~라는 뜻입니다"로 닫는다. 다른 식은 단계 이름으로만 말한다.
4. **컷당 말로 읽는 숫자 2개 이하.** 나머지 수치는 화면에만 둔다. 숫자에는 조건(모델·벤치마크·설정)을 붙인다.
5. 표마다 설정이 다르면(임계값·모델) 그 차이를 결과보다 먼저 말한다.
6. 전문용어는 처음 나올 때 한 번 풀어 말한다("주석, 그러니까 사람이 표시한 위치 정보"). 그 분야의 기본어(AI/CS면 층·벤치마크·처리량)도 푼다.
7. 곁가지(부록 이론, 각주, 학습 환경 세부)는 빼고, 긴 인용은 핵심 절만 읽는다(화면 형광펜은 문장 전체).

**TTS 읽기 표기:** 원고의 영문·숫자는 한국어 읽기로 적는다(AI/CS 예: `엘라바 일점오`, `에스디 알피엔`, `336`은 그대로 두면 `tts.py`가 `삼백삼십육`으로 읽는다). 한 글자 대문자는 `에이`처럼 읽는다. 기호는 말로(`에이 제이`, `마이너스 1`). 약어 읽기는 관례를 따른다(ViCrop = "브이아이크롭"). 화면 자막은 `spec.NAMES`가 다시 영문 표기로 바꾼다.

## 7. 화면

- **논문 제목 카드(프롤로그 끝·에필로그):** 논문 제목은 굵게(`txt(..., 700)`) 쓴다. 300 같은 얇은 굵기는 밝은 바탕에서 묻힌다(사용자 피드백 2026-11-19).

**두 층으로 만든다.**

| 층 | 무엇 | 언제 |
|---|---|---|
| motion 클립 (`clips/`) | motion-broll 스킬로 만든 연속 도형 모션: 카드·막대·슬라이더·토큰 줄·격자·식 카드가 단어에 맞춰 형태를 바꾼다 | 원리·흐름·비교·식·수치처럼 **도형으로 설명하는 모든 장면**(모체 사례: 29개, 영상의 75%) |
| 캔버스 장면 (`scenes.js`) | 실제 자료를 카메라로 밀고 당기는 장면: 사진, PDF 인용 지면, 원문 Figure·Table, 해상도 변화 | 실제 자료를 보여 주는 장면, 클립 사이 짧은 컷 |

- 사용자가 "도형만 나온다"고 거부한 것은 캔버스로 그린 정적 도형이다. 도형 설명은 클립으로 만든다.
- **실제 이미지는 가장 높은 해상도로.** 논문 PDF 내장 이미지(PyMuPDF xref)·400 DPI 크롭(`animatic.py` 도구 — 논문 폴더에 좌표형 `_crop.py`가 있을 때만. 킷의 `autocrop_assets.py` 자산은 PNG를 그대로 자른다)을 쓰고, 공개 데이터셋 사례면 원본을 찾는다(모체 사례: 벤치마크 주석이 가리키는 공개 원본 1600×1200). 외부 원본은 라이선스를 확인하고 `CREDITS.md` + `spec.CREDITS`(그 자료가 나오는 컷에 출처 자막)를 둔다.
- 저해상도 효과(모델이 보는 그림)는 고해상도 원본에서 자연스럽게 흐려지게 보여 주고, 같은 화면에서 원본과 대비한다.
- **밝은 테마(2026-11-19~ 기본).** 바탕 `#F3F2F7`, 카드 흰색 + 테두리 `#CFCCDC`, 글자 `#1F2333`, 강조 진한 주황 `#B5701A` 하나 + 의미색(파랑 `#3F67A8` 배경, 장미 `#B0506A` 잡음·하락, 초록 `#2F8A63` 통과). 정본 팔레트는 `tools/video/theme.py`의 `LIGHT`. 배경 격자·점 무늬를 깔지 않는다.
  - 사용자 피드백(모체 사례): 어두운 바탕(`#10131A`)에 어두운 카드(`#1B2030`)는 경계가 안 보여 따라가기 불편하다. 면과 카드는 명도 차이와 테두리로 구분한다.
  - 어두운 팔레트로 만든 옛 영상을 다시 렌더할 때는 `python tools/video/theme.py "papers/N. name"`으로 클립·장면을 변환하고(원본은 `work/theme_backup/`, 항상 원본에서 변환), beats·stills로 직접 본다.
- 설명용 도식·예시 값에는 "도식"/"예시", codex·데이터셋에서 온 사진에는 "예시 사진"(도식과 한 화면이면 "도식 · 예시 사진"), 비유 장면에는 "비유"를 화면에 단다.
- 화면 하단 25%는 자막 자리, 왼쪽 위는 장 제목 자리(장 첫 4초).
- 장면 함수는 `p`(0~1)만으로 결정되어야 한다(seek 렌더). 시간에 따라 바뀌는 난수 금지.

## 8. motion 클립

1. `clipspec.py`의 `CLIPS`에 클립마다 `id`, `name`, 덮는 연속 컷 `cuts`, `spec`(무엇을 어떤 단어에 보여 주나, 쓸 수 있는 논문 수치)을 적는다. 클립은 서로 겹치지 않는다. 장 첫 컷이 장 제목과 겹치면 첫 4초는 왼쪽 위를 비운다. 사진이 들어가는 클립은 `spec`에 이미지 파일(`assets/…`)·"예시 사진" 표기·이미지 위 상자 좌표를 적는다(2절).
2. `make_video.py <논문> briefs` → `work/briefs/NN-name.md`(길이 T, 단어 시각, 스타일 규칙. 스타일 규칙에 "사진 자리를 도형으로 그리지 않는다"가 들어 있다).
3. 클립 조각 작성은 서브에이전트에 맡길 수 있다. 브리프 경로, `.claude/skills/motion-broll/reference/engine-api.md`, 스킬 예시 `.claude/skills/motion-broll/examples/opus-aoe2/`(품질 기준·시작점)를 준다. **에이전트는 조각 작성·build·beats 점검까지만 하고 렌더는 하지 않는다**(여러 렌더가 겹치면 메모리 부족으로 죽는다).
4. `beats`로 주요 단어 시각의 정지 화면을 뽑아 직접 본다. 잘림·겹침·읽기 어려움·단어와 어긋남이 없을 때까지 고친다. 그다음 `check-assets` FAIL 0(G12 "도형 대체" WARN이 나오면 그 클립을 열어 본다).
5. 렌더는 리드가 `make_video.py <논문> clips-render`로 한 편씩, 포그라운드에서 반복 실행한다.

## 9. 자막

- 화면 자막은 ASS로 입힌다(`finish.py`). 글꼴은 `tools/video/fonts/NotoSansKR-Sub700.ttf`(Noto Sans KR 700 고정 판, 이름 "Noto Sans KR Sub"). **가변 글꼴 NotoSansKR-VF는 기본 굵기가 Thin(100)이라 libass가 가장 얇게 그린다**(사용자 피드백 "글씨가 너무 얇다"의 원인).
- 띠·그림자 없음(사용자 피드백 2026-11-19). `finish.ass`가 자막마다 뒤 화면(아래 가운데)을 세 시점에서 잰다. 표·논문 그림·사진처럼 시각 자료가 깔려 복잡하면(밝기 표준편차 ≥ `BUSY`=22) 아래쪽 어두운 그라데이션(`GRAD`, 62% 검정, blur 70, 페이드 0.3초) + 흰 글자 `Sub`(외곽선 1.2px). 빈 밝은 화면이면 진한 글자 `SubD`(#1F2333, 외곽선 0), 빈 어두운 화면이면 `Sub`. 그라데이션은 0.8초 안으로 이어지는 자막 구간을 한 이벤트로 합쳐 한 장만 그린다(겹쳐 그리면 겹친 곳만 진해지고 가로 경계가 생긴다).
- 줄 나눔은 `finish.split_sub`가 정한다(libass 자동 줄바꿈 끔, WrapStyle 2): 한 줄 ≤ 1480px, 한 자막 ≤ 2줄, 더 길면 여러 자막으로 나누고 시간은 글자 수 비율로 나눈다.
  - 용어는 쪼개지 않는다: 괄호 안, `spec.TERMS`의 `English(한국어)`, `spec.NAMES`의 영문 표기는 한 덩어리(사용자 피드백: "Projector(연결 / 모듈)"처럼 갈림).
  - 쉼표·연결어미(고·며·면·서·지만·는데) 뒤에서 끊기를 선호하고, 관형어·수 표현 뒤("약 | 200개", "한 | 장")와 의존명사·보조용언 앞("할 | 수", "하지 | 않고")에서는 끊지 않는다.
- 겹치지 않게 다음 문장 시작 직전에 끊는다. 장 제목(왼쪽 위)은 진한 글자, 고정 문구·출처는 회색.
- 고유명(모델·장비·데이터셋·약어)은 **영문 그대로**(AI/CS 예: `LLaVA-1.5-7B`, `TextVQA`, `ViCrop`). 전문용어는 **장마다 첫 등장만 `English(한국어)`**(`Attention(어텐션)`). 인용 문장은 번역본 그대로.
- 인용 자막 위에 "저자 · 논문 인용" 표지. 오른쪽 아래 고정 문구, 외부 자료가 나오는 컷은 왼쪽 아래 출처.

| G11 사진 프롬프트 | `video/assets/prompt_*.txt`: UTF-8, `NOT a transparent cutout`, 해상도, 저장 경로, 마지막 줄 6계명 ⑥ (FAIL) · 사진 스타일, 글자·로고 통제, 사람 없음, 확대 대상 위치 % (WARN) | FAIL/WARN |
| G12 예시 이미지 | `sources.json`(없으면 WARN): 모든 이미지 등재, kind별 필수 칸, codex·데이터셋 사진을 쓰는 클립·`scenes.js`에 "예시 사진" 표기 (FAIL) · 명세가 사진 자리를 도형으로 지시하거나 사진 명세인데 이미지 참조가 없는 클립 (WARN "도형 대체") | FAIL/WARN |

육안(사람 또는 Claude가 프레임을 직접 본다):

- **장 경계 틈 9곳 안팎:** 틈 직전·직후 프레임이 같은 장면이어야 한다(다음 장면이 잠깐 비치는 오류는 모체 사례에서 세 번 났다).
- 컷마다 한 프레임씩 시트로 뽑아 자막·장 제목·출처 표기와 겹치는 내용이 없는지 본다.
- 슬라이드 테스트: 아무 프레임이나 발표 슬라이드로 그대로 쓸 수 있으면 실패다.

## 12. 겪은 문제와 대처

## 13. 환경 (새 컴퓨터)

**자동 준비(기본):** 단계 명령(`animatic`, `tts`, `clips-build`, `base-render`, `final` 등)을 실행하면 `make_video.ensure`가 그 단계에 필요한 것을 확인하고 없으면 먼저 설치한다. Node.js·Python 3.12가 없으면 Windows는 winget, macOS는 brew로 설치하고, torch 휠은 GPU를 보고 고른다(RTX 50xx → cu128, 그 밖의 NVIDIA → cu126, 없음 → cpu). TTS 모델은 첫 `tts` 때 Hugging Face에서 내려받는다(인터넷 필요). 끄려면 `VIDEO_NO_AUTOSETUP=1`(motion-broll 스킬 복사는 로컬 복사라 이 값과 무관하게 한다). 수동으로 할 때는 git clone 다음 저장소 루트에서(Windows는 `setup/8_install_video.bat` 더블클릭):

```
python tools/video/make_video.py - doctor      # 빠진 것과 채울 명령을 보여 준다 (motion-broll 스킬이 없으면 설치)
python tools/video/make_video.py - setup       # motion-broll 스킬 · 파이썬 패키지(requirements.txt) · ffmpeg · node_modules · playwright Chromium
python tools/video/make_video.py - setup-tts   # TTS venv tools/video/tts_env (Python 3.12, torch, qwen-tts — 수 GB). 모델은 첫 tts 때 내려받는다
```

- **사전 설치:** Python 3(호스트), Python 3.12(TTS venv, Windows는 `py -3.12`), Node.js LTS, NVIDIA GPU 권장. GPU가 없으면 TTS가 CPU로 돈다(수 배 느림).
- **torch 휠:** 기본 cu126(GTX 10xx~RTX 40xx). RTX 50xx는 `TORCH_INDEX=https://download.pytorch.org/whl/cu128`, `nvidia-smi`가 없으면 자동으로 CPU 휠.
- **저장소에 들어 있는 것(git 추적):** motion-broll 스킬 배포본 `skills/motion-broll/`(MIT, 설치하면 `.claude/skills/motion-broll/`. 클립 조각 작성 기준은 그 안의 `reference/engine-api.md`), 한글 글꼴 `tools/video/fonts/NotoSansKR-VF.ttf`·`NotoSansKR-Sub700.ttf`(OFL, 라이선스 `tools/video/OFL-NotoSansKR.txt`), 목소리 원본 `tools/video/voices/`(내레이터 `f_narrator_high_calm.mp3`, 인용 `m_quote_mid_calm.mp3`, 후보 5개).
- **git에 넣지 않는 것(재설치로 복구):** `.claude/skills/`(스킬 설치본), `tools/video/node_modules`, `tools/video/bin/ffmpeg(.exe)`, `tools/video/tts_env`(venv + 모델 캐시 `hf/` + 목소리 변환본 `ref24/`), 논문별 `video/work/`, `*_video.mp4`. 영상 mp4는 git으로 옮겨지지 않으므로 다른 컴퓨터에서는 다시 만든다(원고·장면·클립 조각이 저장소에 있어 `tts` → … → `final`만 돌리면 같은 영상이 나온다).
- **Chrome:** 기본 화면 렌더(`render.mjs`, `stills.mjs`)는 환경변수 `CHROME` → 흔한 설치 위치 → playwright Chromium 순서로 찾는다(`common.find_chrome`).
- **글꼴:** 자막은 `tools/video/fonts`를 `fontsdir`로 쓴다. 클립은 시스템에 Noto Sans KR이 없으면 `clips-build`가 저장소 글꼴을 HTML에 넣는다. 캔버스 장면은 Google Fonts(IBM Plex Sans KR)를 쓰므로 렌더 중 인터넷이 필요하다.
- 엔진 위치는 환경변수 `MOTION_BROLL`, TTS 파이썬은 `TTS_PY`로 바꿀 수 있다. `TTS_PY`를 주면 `- setup-tts`가 그 venv를 만들고(예: `TTS_PY=D:\tts_env\Scripts\python.exe` — 시스템 드라이브 공간이 부족할 때), 모델 캐시 `hf/`·목소리 변환본 `ref24/`도 그 venv 안에 둔다(`HF_HOME`을 주면 그 값). pip 내려받기 캐시는 `PIP_CACHE_DIR`로 옮긴다. 이후 모든 명령에 같은 `TTS_PY`를 준다.
- TTS 환경·목소리·스킬·글꼴은 모두 저장소 기준 상대 경로로 찾는다(사용자 홈·시스템 글꼴·Chrome 고정 경로 의존 없음).
